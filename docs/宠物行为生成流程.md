# DesktopPet 宠物行为生成流程

## 目标

把“根据一张或多张宠物照片制作桌面宠物”变成可重复、可检查、可升级的生产流程。官方宠物、后续新增宠物和用户上传照片生成的宠物，都使用同一套运行时行为资源，不在 `main.gd` 或 `PetVisual` 中加入宠物名称、品种或坐标特例。

当前标准版本为 `desktop_pet_behavior_v1`。

## 核心原则

1. **先锁定身份，再生成动作**：先完成并由用户确认标准待机母版，所有动作都以照片和同一母版为参考；不得从上一个动作继续递归生成下一个动作。
2. **动作表达变化，身份保持不变**：毛色、花纹、脸型、眼睛、耳朵、尾巴、体型和画风是身份约束，不随动作改变。
3. **统一画布和锚点**：同一宠物的全部运行时图片尺寸完全一致，脚底基线、身体中心和视觉比例一致，切帧时不得漂移或缩放。
4. **小帧数、低频率**：桌面宠物优先使用 1–6 张关键帧和轻量循环，不制作高帧率视频；每只宠物的独立行为贴图最多 24 张。
5. **素材缺失可运行**：`idle_texture` 始终是最终回退。未完成行为包时，宠物仍可使用原有程序形变，不因缺图而消失或报错。
6. **原始照片与发行素材分离**：用户照片不是运行时宠物包的一部分。除非用户明确选择保留，否则完成身份确认和行为生成后应允许删除原始照片。

## 标准行为清单

`idle_texture` 是基础待机图，不放入行为数组。版本一完整行为包必须提供以下行为：

| 行为 ID | 触发类型 | 建议帧数 | 播放建议 | 用途 |
|---|---|---:|---|---|
| `idle_blink` | `RANDOM_IDLE` | 2–3 | `ONCE` | 自然眨眼，最高频的随机动作 |
| `click_happy` | `CLICK` | 2–4 | `ONCE` | 用户点击后的积极回应 |
| `keyboard` | `KEYBOARD` | 2–4 | `LOOP` | 键盘活动陪伴动作 |
| `mouse` | `MOUSE` | 2–4 | `LOOP` | 鼠标点击活动陪伴动作 |
| `focus_calm` | `FOCUS` | 1–4 | `LOOP` | 专注期间的安静状态 |
| `reminder_attention` | `REMINDER` | 2–4 | `LOOP` 或 `PING_PONG` | Focus、喝水或站立提醒 |

以下是推荐的个性动作，不是版本一完整性的硬性要求：

| 行为 ID | 触发类型 | 建议帧数 | 建议冷却 |
|---|---|---:|---:|
| `idle_look` | `RANDOM_IDLE` | 2–4 | 15–30 秒 |
| `idle_yawn` | `RANDOM_IDLE` | 3–6 | 60–120 秒 |
| `idle_stretch` | `RANDOM_IDLE` | 3–6 | 90–180 秒 |

睡觉、头部抚摸、耳朵、背部、前爪和尾巴互动会在对应触发条件实现后加入新版本标准；版本一不使用无法触发的占位行为。

## 推荐目录

现有旧宠物包可以继续使用平铺文件。新生成的宠物建议采用：

```text
assets/pets/<pet_id>/
├─ pet.tres
├─ runtime/
│  ├─ idle.png
│  └─ behaviors/
│     ├─ idle_blink/
│     │  ├─ frame_001.png
│     │  └─ frame_002.png
│     ├─ click_happy/
│     └─ ...
└─ authoring/
   ├─ .gdignore
   ├─ identity-master-chroma.png
   ├─ identity-sheet.png
   ├─ behavior-contact-sheet.png
   └─ generation-manifest.json
```

- `runtime` 只保存游戏需要的透明 PNG。
- `authoring` 保存可选的制作过程文件，并通过 `.gdignore` 避免 Godot 导入和正式导出。
- 用户原始照片默认保存在应用用户数据区的临时项目中，不复制到 `assets/pets`，也不写入 `generation-manifest.json`。

## 图片规格

- 作者母版建议为 1024–1536 像素方形画布。
- 运行时版本建议统一缩小为 512×512；同一宠物必须全部采用相同尺寸。
- 当前旧宠物使用 1254×1254 母版，新增行为前可以先整体转换成统一运行时尺寸；不得只缩小动作帧而保留不同尺寸的待机图。
- PNG 使用直通 alpha，边缘不得带白边、黑边、色键残留或半透明噪点。
- 角色在所有帧中使用相同身体中心与脚底基线。
- 最夸张动作也必须留在统一安全画布内，不能依赖运行时临时扩大图片。
- 第一帧和最后一帧应尽量能自然回到 `idle_texture`；可直接在行为帧数组中复用 `idle_texture`，减少独立贴图数量。

## 标准生成流水线

### 1. 照片接收与质量检查

优先收集：

- 正脸或略微俯视的清晰头像；
- 能看清四肢、尾巴和身体比例的全身照；
- 左右侧或三分之二侧面照；
- 能准确表现毛色、眼睛和独特花纹的补充照片。

照片不足时可以生成，但必须标记不确定特征并让用户确认，不擅自补成另一个品种的典型外观。

### 2. 身份摘要

在生成图片前先记录稳定特征：

- 物种和大致品种；
- 身体比例、体型与毛长；
- 头型、耳型、眼睛颜色与间距；
- 口鼻、胸口、四肢、尾巴的颜色和花纹；
- 必须保留的独特特征；
- 应避免的错误，例如 Leo 眼下白线、黑色四肢粘连或 Mable 过于严厉的眉眼。

身份摘要是后续所有行为提示词的固定输入。

### 3. 标准待机母版

先只生成中性待机姿势：

- 面向屏幕或轻微三分之二角度；
- 四肢和尾巴轮廓清晰；
- 表情自然、友善；
- 构图居中并留足动作安全边距；
- 画风与已发布宠物保持一致。

用户确认母版后才进入批量行为生成。母版改变时，旧行为帧应视为失效并重新生成，避免混用两个身份版本。

### 4. 行为帧生成

每个行为都从“原始照片 + 已确认身份母版 + 固定身份摘要”重新开始。提示词由三部分组成：

```text
[固定身份与画风约束]
[本行为唯一允许变化的姿势、表情和部位]
[统一画布、相机、光线、透明背景与禁止项]
```

禁止项至少包括：

- 不改变品种、毛色、花纹、眼睛颜色和年龄；
- 不增加或减少四肢、耳朵、尾巴；
- 不改变相机距离、角色比例、画布和脚底基线；
- 不添加文字、道具、场景背景或不一致的投影；
- 不产生眼周白边、锯齿、色键溢色和透明噪点。

### 5. 抠图与对齐

每帧保留两种制作文件：

- 色键或未清理母版，用于返工；
- 去背景后的透明运行时 PNG。

黑色或深色宠物不得用白色描边补轮廓。应通过柔和的局部高光、身体内部明度分层和干净 alpha 边缘区分四肢。抠图后必须检查眼睛、胡须、耳缘、脚趾和尾巴等高对比区域。

### 6. 自动校验

`PetBehaviorProfile.validation_errors()` 负责版本一结构检查：

- 核心行为是否齐全、ID 与触发类型是否匹配；
- 行为 ID 是否重复；
- 每个行为是否有有效图片；
- 所有帧是否与待机图尺寸一致；
- 每个行为是否超过 6 帧；
- 每只宠物是否超过 24 张独立行为贴图；
- `focus_calm` 是否使用循环播放。

自动校验不替代视觉检查。身份漂移、白边、肢体粘连和动作是否自然仍需接触表与人工确认。

### 7. 接触表与用户确认

为每个宠物生成一张行为接触表，至少显示：

- 标准待机图；
- 每个行为的关键帧；
- 行为 ID；
- 首尾帧切换预览；
- 透明背景和深浅两种测试底色。

只有通过身份一致性、轮廓、对齐和表情确认的图片才进入 `runtime`。

完整宠物包可以使用项目工具生成标准接触表：

```powershell
python tools/generate_behavior_contact_sheet.py `
  --pet-dir assets/pets/<pet_id>
```

工具固定检查六项核心行为，并自动把运行时目录中发现的可选行为追加到接触表；
每张独立关键帧都会同时放在浅色和深色背景上，并默认保存到
`assets/pets/<pet_id>/authoring/behavior-contact-sheet.png`。任一核心行为缺失时
命令会失败，避免用不完整接触表进行验收。

### 8. 打包与运行验收

把行为资源加入 `pet.tres` 后检查：

- 随机动作遵守权重和冷却；
- Focus 期间不会播放未允许的随机动作；
- 键鼠动作不会覆盖点击和提醒；
- 鼠标动作只表达通用点击反馈，不得依赖、暗示或推断未采集的光标坐标；
- Reminder 可以覆盖其他短动作；
- 连续同类键鼠批次只延长当前动作，不得反复重置第一帧；
- 切帧不改变宠物在桌面上的位置；
- 缺少任意可选行为时回退到待机图和原有程序动作；
- 75%–300% 缩放、浅色和深色桌面背景下均无明显边缘问题。
- 编辑器中的统一动作预览窗口会从当前宠物包动态列出并触发所有已配置行为；
  动作较多时列表可滚动，未知自定义行为 ID 也有可读标签。

## 运行时数据

每个 `PetBehaviorDefinition` 包含：

- `behavior_id`：稳定行为 ID；
- `trigger`：随机待机、点击、键盘、鼠标、专注或提醒；
- `frames`：按顺序播放的透明 PNG；
- `frames_per_second`：轻量帧速；
- `playback`：单次、循环或往返；
- `play_duration_seconds`：可选的明确持续时间；
- `weight`：同类行为的随机权重；
- `cooldown_seconds`：再次选择前的冷却；
- `allowed_during_focus`：Focus 期间是否允许继续。

运行时优先级固定为：

```text
Reminder > Click > Keyboard/Mouse > Random Idle
```

宠物包不能提高自身优先级，避免用户生成素材破坏提醒和交互逻辑。

## 后续自动化

版本一先固定数据结构、生成规范和校验入口。后续生成工具应按同一顺序提供：

1. 照片导入与本地隐私选择；
2. 自动身份摘要和用户修正；
3. 待机母版生成与确认；
4. 按标准行为列表排队生成；
5. 自动抠图、对齐、尺寸与资源预算检查；
6. 接触表预览和逐项重试；
7. 自动写入 `pet.tres` 并安装到用户宠物目录。

生成工具只负责生产标准宠物包；游戏运行时不直接依赖特定图像模型或服务。
