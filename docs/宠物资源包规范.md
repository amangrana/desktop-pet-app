# DesktopPet 宠物资源包规范

## 目标

普通新宠物应只通过新增一个自包含文件夹接入，不修改 `main.gd`、`Main.tscn`、`PetRegistry` 或 `PetVisual`。

照片到完整动作包的标准生产与验收流程见
[`宠物行为生成流程.md`](宠物行为生成流程.md)。运行时行为数据使用
`desktop_pet_behavior_v1` 版本规范。

## 目录约定

```text
assets/pets/<pet_id>/
├─ pet.tres
├─ dialogue.tres    可选
├─ dialogue/        配置对白时必需
│  └─ locales/
│     ├─ en.tres    必需的英语回退
│     └─ zh_CN.tres 可选；其他语言使用相同方式新增
├─ idle.png
├─ click.png       可选
├─ keyboard.png    可选
├─ mouse.png       可选
└─ runtime/
   └─ behaviors/   新行为包推荐使用
```

- 文件夹名称和 `pet_id` 使用稳定的小写英文 ID，例如 `leo`、`milo_cat`。
- `display_name` 是显示给玩家的名称，可以本地化。
- `pet.tres` 必须直接或间接引用运行时需要的全部素材。
- 原始分层文件、色键母版和生成过程文件可以保留，但不应被 `pet.tres` 当作运行时贴图。

## 必填字段

| 字段 | 用途 |
|---|---|
| `pet_id` | 存档和切换使用的稳定唯一 ID；发布后不要改名 |
| `display_name` | 窗口标题和切换菜单显示名称 |
| `idle_texture` | 默认显示图，也是所有缺失动作的回退图 |
| `display_size` | 桌面上渲染贴图的逻辑尺寸 |
| `interaction_polygon` | alpha 轮廓生成失败时使用的 Windows 鼠标接收和可见形状安全区，至少 3 个点 |

## 快捷操作热点

宠物包可以配置一个或多个前爪专注快捷操作：

- `focus_hotspot_centers`：一个或多个热点中心，使用与 `interaction_polygon` 相同的宠物本地坐标。
- `focus_hotspot_radius`：所有圆形热点共用的点击半径；设为 `0` 或不给出中心表示该宠物不提供前爪快捷操作。
- 双爪宠物通常为两个前爪各配置一个中心；应尽量避开身体和大面积透明区域。
- 普通点击仍触发宠物互动；只有短按热点才启动专注。拖动优先，不得因从热点开始拖动而误触。

## 可选动作与回退

- `click_texture`：点击互动姿势。
- `keyboard_texture`：键盘活动姿势。
- `mouse_texture`：鼠标点击活动姿势。
- 任一可选动作未提供时，通用显示组件自动使用 `idle_texture`。
- 所有动作贴图应使用相同画布、角色比例和锚点，避免切换时跳动。

以上三个单图字段是旧宠物包兼容入口。新行为包应优先在 `behaviors`
数组中配置 `PetBehaviorDefinition`，从而支持多帧、触发类型、播放方式、
权重和冷却。行为数组未提供或某一行为无效时，仍安全回退到旧字段和
`idle_texture`。

版本一核心行为 ID 固定为 `idle_blink`、`click_happy`、`keyboard`、
`mouse`、`focus_calm` 和 `reminder_attention`。宠物包不能通过配置修改
运行时优先级；固定顺序为 Reminder > Click > Keyboard/Mouse >
Random Idle。

## 点击特效

每只宠物可以配置：

- 是否显示点击爱心。
- 爱心位置、大小和颜色。
- 点击跳跃高度。

运行时优先把 `idle_texture` 缩小到逻辑显示尺寸，根据 alpha 自动生成简化轮廓，并加入少量动作安全边距和点击爱心连接区域。这样透明角落允许鼠标穿透，同时避免呼吸、跳起或爱心被 Windows 窗口形状裁掉。

`interaction_polygon` 仍是必填回退值，必须覆盖角色在点击上移后的完整轮廓以及爱心等窗口内特效。贴图无法读取或 alpha 轮廓生成失败时会使用它。Windows 下鼠标接收多边形也可能表现为可见窗口形状，因此回退轮廓的斜边不得穿过素材。

## 可选人格对白

- `dialogue_profile` 可引用自包含的 `PetDialogueProfile`；没有档案的宠物继续正常运行且不显示对白。
- 当前规范版本为 `desktop_pet_dialogue_v2`，标准上下文包括 `click`、`focus_start`、`focus_complete`、`reminder_done` 和 `idle`。
- 每个 `PetDialogueEntry` 只保存稳定上下文、候选对白 ID 和独立冷却，不直接保存任何语言文本。对白 ID 建议使用 `<pet_id>.<context>.<number>`，发布后保持稳定。
- `dialogue/locales/*.tres` 中每个 `PetDialogueLocale` 保存一个 `locale_code` 和“对白 ID → 文本”字典；运行时自动扫描该目录。新增语言只需复制一个语言文件并翻译文本，不修改 `dialogue.tres`、宠物定义或核心脚本。
- `en.tres` 是必需的逐句回退；其他语言允许暂时缺少个别 ID，运行时依次尝试完整地区代码、基础语言和 English。例如 `fr_CA` 会先尝试 `fr_ca`、再尝试 `fr`、最后使用 `en`。
- 单句不得包含换行，最长 96 个字符；显示层仍会按实际字体与缩放比例安全省略。档案校验会拒绝缺少英语回退、重复 ID、重复语言或不合规文本。
- 档案可以设置全局冷却和空闲对白的最小/最大间隔。空闲对白必须保持低频，并让健康提醒、Focus、Pet Notes、勿扰和设置窗口优先。
- Developer 对白预览不消耗正常运行时冷却；普通新宠物只需在自己的资源包中新增档案和语言文件，不修改核心调度代码。
- 预写对白是未来 AI 断网、未连接或额度不足时的本地回退层，不包含 API 密钥、聊天记录或长期记忆。

## 自动发现与排序

- `PetRegistry` 扫描 `assets/pets` 的直接子目录。
- 只有包含有效 `pet.tres` 的目录会进入宠物列表。
- 重复 `pet_id`、缺少待机图或无效轮廓会被忽略并产生警告。
- 先按 `sort_order` 排序，相同时按 `display_name` 排序。

## 新宠物验收

- 启动时自动出现在右键菜单。
- 切换后窗口标题、贴图和点击轮廓立即更新。
- 重启后恢复上次选择。
- 点击、键盘和鼠标预览不会报错。
- 缺少可选动作图时正确回退。
- 完整行为包通过 `PetBehaviorProfile.validation_errors()` 校验。
- 所有行为帧尺寸与 `idle_texture` 完全一致，每项最多 6 帧，每只宠物
  最多 24 张独立行为贴图。
- 随机行为遵守权重和冷却，Focus 期间不播放未允许的随机行为。
- Reminder 覆盖点击、键鼠和随机动作；键鼠动作不得覆盖点击。
- 在 75%、100%、125%、150%、200%、250% 和 300% 缩放下不裁切角色或特效。
- 透明区域尽量允许鼠标穿透，角色和互动区域可以可靠点击。
- 短按任一前爪热点可以开始专注，热点外的普通点击不会开始计时。
- 从任一前爪热点拖动宠物不会误触专注。
- 可选对白档案通过版本、重复上下文、稳定对白 ID、英语回退、语言资源和单行长度校验；缺失或无效档案安全回退。
